# Quickstart: 과제 운영·평가·성적 환류 자동화 검증

이 기능이 실제로 동작하는지 확인하는 최소 절차다. 구현 세부(함수 본문, 실제 코드)는 다루지 않고,
무엇을 실행해서 무엇이 보이면 성공인지만 정리한다. 데이터 모델은 [data-model.md](./data-model.md),
설계 근거는 [research.md](./research.md), 상세 요구사항은 [spec.md](./spec.md)를 참고한다.

## 사전 준비

- 이 기능 전용의 새 Google 스프레드시트 + `assignment-automation/` Apps Script 프로젝트(clasp로
  push된 상태).
- 테스트용 Google Classroom 코스 1개(이 스크립트가 만들 것이므로 빈 코스면 충분).
- 소수(2~3명)의 테스트 학생 계정.

## 시나리오 1 — 초기 설정 (User Story 1)

1. 빈 스프레드시트에서 메뉴로 구성 시트 생성을 실행한다.
2. **확인**: 강좌설정·역량과제정의·수강생·주차·Forms·역량과제·변경이력 시트가 생성되고, 역량과제정의에
   즉시 동작하는 예시 유형이 채워져 있다.
3. 강좌설정에 학기·코스식별자·교사이메일 등 필수값을 입력하고, 수강생 2~3명, 주차 1개(수업일을
   "지금부터 2분 후"로 설정 — 즉시 트리거되게 하기 위함)를 등록한다.
4. 정합성 검증을 실행한다. **확인**: 통과 메시지가 뜨고 이후 단계 진행이 허용된다. (실패 케이스를
   보고 싶으면 등급구간 하한을 오름차순으로 일부러 넣고 재실행 — 구체적 위반 사유가 나와야 한다.)

## 시나리오 2 — 과제 생성부터 게시까지 (User Story 2, 3)

1. 등록한 주차를 지정해 과제 행 생성을 실행한다.
2. **확인**: Forms 시트에 역량과제정의의 유형 수만큼 행이 생기고, 시작·종료가 자동 계산돼 있다.
3. 몇 분 기다린다(또는 트리거를 수동 실행). **확인**:
   - 각 활성 행에 생성 Form·응답 시트 링크가 채워진다.
   - Google Classroom 코스에 그 폼이 첨부된 과제가 게시된다.
   - 역량과제 대장에 학생×과제 조합 행이 생긴다.
   - 시작 시각이 지나면 게시상태=게시, 진행상태=수집중으로 바뀐다.
4. 종료 시각을 지나도록 기다리거나 앞당겨 재실행한다. **확인**: 진행상태가 채점중으로 바뀌고
   제출/미제출 수가 채워진다.

## 시나리오 3 — 평가부터 성적 반환까지 (User Story 4, 드라이런)

1. 강좌설정의 드라이런 토글을 켠 채로 평가 항목 열 준비를 실행한다. **확인**: 응답 시트에 평가
   항목 열(드롭다운/수식)이 생긴다.
2. 응답 시트에서 항목별 판정을 입력한다(테스트 학생 전원).
3. 평가 수집 → 점수 산정 → 성적 전송(드라이런)을 순서대로 실행한다. **확인**:
   - 역량과제 대장에 원점수·점수·수집상태=완료가 채워진다.
   - 드라이런이므로 Classroom에는 실제로 반영되지 않고, 반영될 값만 로그/미리보기로 확인된다.
4. 드라이런을 끄고 다시 실행한다. **확인**:
   - Classroom에서 학생 계정으로 로그인해 점수가 보인다.
   - 변경이력 탭에 이번에 반영된 건수만큼(스킵/조회 제외) 시각·대상·이전값·이후값 행이 추가된다.
   - 같은 상태로 한 번 더 실행하면 변경이력에 새 행이 추가되지 않는다(멱등 확인).
   - 진행상태가 반환완료로 바뀐다.
   - (학생통지 토글이 켜져 있으면) 테스트 학생 메일함에 개인 피드백 메일이 온다.

## 시나리오 4 — 동시성/멱등 확인 (FR-060, FR-061)

1. 방금 반환완료까지 끝난 과제에 대해 성적 전송을 한 번 더 수동 실행한다. **확인**: 어떤 학생의
   제출물도 다시 쓰이지 않고(변경이력 증가 없음), 실행이 빠르게 끝난다.
2. (선택, 코드로 검증) 같은 처리를 의도적으로 거의 동시에 두 번 트리거해본다. **확인**: 하나는
   정상 처리되고 다른 하나는 잠금 획득 실패로 즉시 조용히 종료되어, 같은 상태 전이가 두 번
   기록되지 않는다.

## 시나리오 5 — 순수 함수 단위 테스트 (헌법 V)

```bash
cd assignment-automation
node test/run.js
```

**확인**: `scoring.js`(등급구간 판정), `studentId.js`(학번 정규화), `stateTransition.js`
(게시상태·진행상태 전이 판정), `gradeSendPolicy.js`(성적 전송 여부/멱등 판정) 4개 모듈의 모든
분기가 통과로 표시된다. 이 4개 외의 모듈에는 테스트가 없어도 실행이 실패하지 않는다.

## 완료 기준

시나리오 1~5를 모두 통과하면, 정상 경로가 "사람 개입 0회"(과제 행 생성·평가 입력 제외)로 폼 생성부터
성적 반환·통지까지 이어진다는 이 기능의 핵심 가치(SC-001, SC-005)가 검증된 것이다.
