# Phase 1 Data Model: 과제 운영·평가·성적 환류 자동화

모든 엔티티는 이 기능이 바인딩되는 단일 스프레드시트의 시트(탭)로 구현된다. 열은 항상 헤더 이름으로
조회되며(헌법 IV), 배경색으로 교사 입력/자동 계산/시스템 기록 구역을 구분한다(FR-002).

## 강좌설정

키-값-설명 3열. 코드가 읽는 유일한 설정 출처(FR-049).

|---|---|---|

## 역량과제정의

1행 = (역량과제 유형, 평가항목) 조합. 유형 단위 속성은 그 유형의 첫 행에만, 항목 단위 속성은 매
행에 입력된다.

| 열 | 구분 | 타입 | 검증 |
|---|---|---|---|
| 역량과제유형 | 항목 반복 | 문자열 | 매 행 반복 입력(그룹 키) |
| 템플릿Form | 유형 단위 | Drive 파일 ID | 첫 행만, 나머지 행은 공백 |
| 팀평가여부 | 유형 단위 | 불리언 | 첫 행만 |
| 시작오프셋 | 유형 단위 | 기간(일/시간) | 수업일 기준 상대값, 첫 행만 |
| 기간 | 유형 단위 | 기간 | 시작→종료 길이, 첫 행만 |
| 등급구간 | 유형 단위 | 문자열(직렬화된 하한:반영값 목록) | 첫 행만. 하한 내림차순, 마지막 하한 0, 중복 없음, 최고 하한 ≤ 만점 |
| 평가항목 | 항목 단위 | 문자열 | 유형 내 중복 금지 |
| 배점 | 항목 단위 | 정수 ≥ 0 | 유형별 배점 합 > 0 |
| 선택지 | 항목 단위 | 문자열(구분자 목록) | 판정수식과 상호 배타(하나만 채움) |
| 판정수식 | 항목 단위 | 문자열(스프레드시트 수식 텍스트) | 같은 응답 시트 열만 참조(다른 시트 참조 금지) |
| 기준값 | 항목 단위 | 문자열/숫자 | 판정수식이 참조하는 임계값 |

**파생값**: 만점 = 그 유형에 속한 모든 행의 배점 합(저장값 아님, 참조 계산).

**불변 규칙**: 학기 중 값 변경 금지(FR-050). 변경이 필요하면 예외 복구(소급 재계산, FR-045)로만
처리.

### 진행상태 상태 전이도

```
대기 --(시작 시각 도달, FR-019)--> 수집중 --(종료 시각 도달, FR-020)--> 채점중
채점중 --(모든 대상 학생 원점수 확정, FR-028)--> 평가완료
평가완료 --(모든 대상 학생 성적 전송 완료, FR-031)--> 반환완료
(모든 상태) --(재시도 한도 초과)--> 오류 --(교사 예외 복구, FR-043)--> 재진행(직전 상태로 복귀)
연계 과제(문제 만들기)만: 채점중 --(연계 퀴즈 채점 완료, UC-19/FR-040)--> 평가완료
```

게시상태는 진행상태와 별도로 대기 → 게시(수집 시작 시) → (실패 시) 오류로만 전이한다.

## 역량과제 (평가·성적 대장)

과제×학생 조합 1건 = 1행.

| 열 | 타입 | 검증 |
|---|---|---|
| 주제 / 역량과제 | 참조 | Forms 행과의 조인 키 |
| 이름 / 학번 | 참조(수강생) | 학번은 정규화 비교 |
| 평가 | 문자열 | 항목별 판정 텍스트(사람이 읽는 형태) |
| 원점수 | 숫자 | 제출물 없으면 0으로 확정(FR-026) |
| 만점 | 참조(계산값) | 역량과제정의 배점 합을 가리키는 참조, 저장값 아님 |
| 피드백 | 문자열(선택) | 서술형, 통지 본문에만 쓰이고 로그에는 남기지 않음 |
| 점수 | 숫자 | 등급구간 적용 결과(반영값) |
| 수집상태 | 열거형: 대기\|완료 | Forms의 진행상태와는 다른, 학생 단위 필드(FR-025~027) |
| 반영 | 숫자 | = 점수와 동일 값을 가리키는 표시용 별칭(UI 표기 목적) |
| 비고 | 문자열(선택) | |

## 응답 시트

생성 Form에 연결된 시트. 역량과제정의의 평가항목마다 열이 추가되며, 판정수식이 있는 항목은 실제
셀 수식으로 이식된다(research.md #5). 팀평가 유형은 팀별 대표 행이 최초 1회 고정 기록된다
(FR-023) — 별도 시트나 열이 아니라 이 시트 안의 숨은 "대표행여부" 플래그 열로 관리한다.

## 등급구간

역량과제정의의 한 유형에 속하는 값 목록(직렬화되어 그 유형 첫 행 셀 하나에 저장). `scoring.js`가
파싱해 `{하한, 반영값}[]` 배열로 다룬다. 순수 로직 계약:

```
scoreToGrade(rawScore, bands) -> band.반영값
  bands는 하한 내림차순으로 정렬되어 있다고 가정(정합성 검증에서 이미 보장)
  첫 번째로 rawScore >= band.하한 을 만족하는 band를 반환
```

## 연계 과제 관계

문제 만들기 유형과 퀴즈 풀기 유형 사이의 관계. 별도 테이블이 아니라 코드가 인식하는 고정 유형 이름
쌍(research.md 전제, `/speckit-clarify` Assumptions)으로 표현되며, 같은 주제(주차 시트 참조)를 통해
런타임에 연결된다.
